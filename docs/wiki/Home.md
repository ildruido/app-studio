# app-studio wiki

**app-studio** is the master copy of the harness used to build apps with Claude Code Projects: skills, agents, hooks, templates and stack packs. You describe what you want in plain words; Claude plans, builds, tests, merges and ships it. Nothing in app-studio is about one app: each app describes itself in an App profile in its own `CLAUDE.md`.

## Start here

- New to app-studio? Read [Concepts and roles](Concepts-and-roles).
- Setting up for the first time? [Set up once](Set-up-once), then [Start a new app](Start-a-new-app).
- Building an app day to day? [Everyday workflow](Everyday-workflow) and [How PRs merge](How-PRs-merge).
- Updating an app, or sending an idea back? [Update an app](Update-an-app) and [Send a harness idea](Send-a-harness-idea).
- Changing app-studio itself? [Change app-studio itself](Change-app-studio-itself).
- Choosing what an app can do? [Packs and modules](Packs-and-modules) and [Known limits](Known-limits).

## Who reads what

| You are | Read |
| --- | --- |
| **App Creator** (product owner of an app) | Concepts, Start a new app, Everyday workflow, Update an app, Send a harness idea, Known limits |
| **Tester** | Everyday workflow (testing a release) |
| **Admin** (does the clicks only a person can) | Set up once, How PRs merge, Start a new app (one-time repo settings) |
| **App-Studio Owner** (product owner of the harness) | Concepts, How PRs merge, Change app-studio itself |

The rules for changing app-studio are in `docs/GOVERNANCE.md` in the repository. This wiki is a friendlier guide to them, and is generated from `docs/wiki/` in the repository: change a page there, not in the wiki.
