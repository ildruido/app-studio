# 4b · Project instructions templates (read-only analysis)
Files: `plugins/studio/templates/project-instructions.md` (app template, ~5.1K chars ≈ 1.3K tokens) and `docs/studio-project-instructions.md` (studio, ~3.3K chars ≈ 0.85K tokens; this Project's own text).
Frequency: the app text is loaded by EVERY thread AND the coordinator in every app Project, every turn-start. The studio text likewise in this Project. Small, but the highest-multiplier text in the harness. It is prose rules for the model; nearly nothing in it is code-able.

## Candidates
- **P1 · Both files · "subscribe to PR + 3-min check-in + unsubscribe + confirm merged" bullet** (~85 tokens x2 files, also in CLAUDE.md "Git workflow" per 4a). Duplicated in template CLAUDE.md. Keep one line here pointing to CLAUDE.md (app) / GOVERNANCE s5 (studio). Needs-judgement (a thread must still behave right if CLAUDE.md is unread; thread-start order says it reads CLAUDE.md first, so fairly safe). Saving ~100-150 tokens per thread start.
- **P2 · App · "Open every PR ready, never draft; read back, mark ready"** (~90 tokens). Already enforceable: a hook/CI could flag `draft: true` on a harness PR, or `pr-status` (4a·T2, 3·C1) prints it. Then the rule shrinks to one clause. Safe for the check; wording trim needs-judgement. ~60 tokens/thread; larger value is reliability (draft PRs fail silently).
- **P3 · App · "harness loaded" start-up-message fallback bullet** (~100 tokens). Already duplicated by 4a·T1 (fallback printed by the session hook only when the env isn't loaded). Reduce to "if the start-up message says the harness did NOT load, follow it". Safe once T1 is done. ~80 tokens/thread.
- **P4 · App coordinator · "Point, don't repeat" bullet** (~230 tokens, longest bullet; the studio copy is ~90). Policy text, must stay model-read. Trim to the studio-length wording + a shared definition in GOVERNANCE. Needs-judgement (routing was live-checked in 0.28.0/0.28.1; wording changes re-trigger a live check). ~130 tokens per coordinator turn.
- **P5 · App coordinator · backlog-id bullet** ("name ids after checking BACKLOG, BACKLOG-DONE on main and open PRs"). Becomes one clause once `backlog next` exists (2b): "ask `backlog next --reserve N`". Safe after 2b. ~60 tokens, rare.
- **P6 · Both · Models/threads ("Sonnet at medium effort...") and "never resume idle thread" bullets** repeated in 4a·T5 (CLAUDE.md). Keep in the Project instructions only (coordinator-only), delete from CLAUDE.md: saves in CLAUDE.md, not here. Needs-judgement (the "unverified" caveat in 4a stands). ~0 here.
- **P7 · Audience line + intro** (~60 tokens x2): needed so the same text isn't misapplied. Keep.
- **P8 · Drift detection (already scripted, extend)**: `studio-sync` hashes the app template (`instructionsHash`, `instructionsNote`) and prints a ready prompt; the studio text has NO equivalent, only the `tier.mjs` wording-doc list. A script could diff each Project's live text against the template and print the exact missing/changed bullets (the model currently "compares" two ~1.3K texts, ~3K tokens per sync that flags it). Needs a way to read the live Project text (coordinator-only API) so the script can only diff a pasted copy: needs-judgement. ~2-3K tokens per flagged sync, rare.
- **P9 · Studio · "merge by tier" bullet** (~170 tokens): mirrors GOVERNANCE s5/s9. A `pr-status`/tier script already decides the tier (`tier.mjs`); bullet could shrink to "merge by tier: run `tier` / see GOVERNANCE s9". Needs-judgement (must stay explicit about owner-ok). ~100 tokens/thread.

## Overall
Most of these two files must stay as model-read policy: there is little to turn into code. Total realistic trim: ~300-500 tokens per thread start in apps (about a third of the file), ~250 in the studio, all needs-judgement or dependent on earlier findings (T1, 2b backlog, C1 pr-status). Small per-load, but loaded by every thread and every coordinator turn, so across a busy app the sum is still meaningful. Lowest-risk first step: P1+P3 (pure duplication). Wording changes to the app template trigger the sync "instructions changed" reminder in every app and a live check (GOVERNANCE s7), so batch them with 4a·T9/T2 trims rather than shipping alone.
